# HillGPX architecture

## Overview

HillGPX is a static web app. All data is committed JSON or GPX; the browser never talks to a backend. Deployment is GitHub Pages.

```
┌─────────────────────────────────────────────────────────┐
│  Browser                                                │
│  React + MapLibre GL                                    │
│  localStorage for favourites and saved routes           │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼ reads
┌─────────────────────────────────────────────────────────┐
│  public/data/venues.json                                │
│  public/data/routes.json                                │
│  public/data/dem/sg-dem.{json,bin}  (Singapore only)    │
│  public/photos/*.webp                                     │
└─────────────────────────────────────────────────────────┘
                           │ generated by
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Python pipeline                                        │
│  scripts/build_data.py                                    │
│  scripts/fetch_dem.py                                     │
│  scripts/fetch_peaks.py                                   │
│  scripts/ingest_hdb.py                                    │
│  scripts/fetch_photos.py                                  │
└─────────────────────────────────────────────────────────┘
                           │ reads
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Source data                                            │
│  data/venues/hills.json                                   │
│  data/venues/hdb-blocks.json                              │
│  data/venues/peaks.json                                   │
│  data/routes/*.gpx                                        │

```

## Module boundaries

### Frontend

| Module | Responsibility | Key files |
|---|---|---|
| Shell | URL routing, layout, list/map split | `src/App.tsx` |
| Map | MapLibre init, markers, viewport grid, layer toggles | `src/map/MapView.tsx`, `src/map/markers.ts`, `src/map/layers.ts`, `src/map/constants.ts` |
| Venue UI | Cards, detail page, search, filters, units | `src/components/VenueCard.tsx`, `src/components/VenueDetail.tsx`, `src/components/SearchBar.tsx`, `src/components/FilterBar.tsx`, `src/components/ResultsList.tsx`, `src/components/UnitsContext.tsx` |
| GPX profiling | File drop, parse, elevation profile, local save | `src/components/GpxDropzone.tsx`, `src/components/GpxPanel.tsx`, `src/components/ElevationProfile.tsx`, `src/lib/gpx.ts`, `src/lib/elevation.ts`, `src/lib/localRoutes.ts` |
| Domain helpers | Venue matching, route building, units, glyph mapping | `src/lib/venues.ts`, `src/lib/routes.ts`, `src/lib/units.ts`, `src/lib/venueGlyphs.ts` |

| Styles | Global CSS, no CSS-in-JS | `src/styles.css` |

### Data pipeline

| Script | Input | Output | Credentials |
|---|---|---|---|
| `build_data.py` | `data/venues/*.json`, `data/routes/*.gpx` | `public/data/venues.json`, `public/data/routes.json` | None |
| `fetch_dem.py` | AWS Open Data terrain tiles | `public/data/dem/sg-dem.json`, `sg-dem.bin` | None |
| `fetch_peaks.py` | OpenStreetMap Overpass | `data/venues/peaks.json` | None |
| `ingest_hdb.py` | data.gov.sg + OneMap | `data/venues/hdb-blocks.json` | OneMap |
| `fetch_photos.py` | Mapillary API | `public/photos/*.webp` | Mapillary token |

## Data contracts

All coordinates are `[lng, lat]` or `[lng, lat, elevation]` unless otherwise noted. Elevations are in metres. Distances are in metres.

### Venue (`src/types.ts`)

```ts
interface Venue {
  slug: string;
  name: string;
  type: VenueType;
  lat: number;
  lng: number;
  summitM?: number | null;
  gainM: number | null;
  elevationSource: ElevationSource;
  routeSlugs: string[];
  // optional fields omitted when null in generated output
}
```

Rules:

- `slug` is kebab-case, unique, stable. It links venues to routes.
- A venue with both `summitM` and `gainM` missing is dropped at build time.
- `elevationSource` must be one of `estimated | dem | community | verified`.
- `routeSlugs` is populated by `build_data.py` based on route proximity.

### Route (`src/types.ts`)

```ts
interface Route {
  slug: string;
  name: string;
  venueSlugs: string[];
  distanceM: number;
  gainM: number;
  lossM: number;
  loop: boolean;
  surface?: RouteSurface;
  difficulty?: RouteDifficulty;
  coordinates: RoutePoint[];
  source: 'curated' | 'community' | 'local';
  contributor?: string;
  description?: string;
}
```

Rules:

- `coordinates` are `[lng, lat, elevationM]`, simplified by Douglas-Peucker.
- `gainM` and `lossM` are computed with a 2 m noise threshold and a 5-point smoothing window.
- `loop` is true when the first and last points are within 100 m.
- Optional sidecar JSON may override auto-detected `surface`, `difficulty`, `description`, `contributor`, or venue links.

### Terrain model (`public/data/dem/sg-dem.json`)

```ts
interface DemHeader {
  west: number;
  south: number;
  east: number;
  north: number;
  width: number;
  height: number;
  noData: number;
  attribution: string;
}
```

The sibling `.bin` file is a row-major `Int16Array` of size `width * height`. Values are metres above sea level; `noData` marks missing samples.

## Build flow

1. Curated venues load first from `data/venues/hills.json`.
2. OSM peaks load from `data/venues/peaks.json`; peaks within 250 m of an existing venue are dropped as duplicates.
3. HDB blocks load from `data/venues/hdb-blocks.json`.
4. Photos attach by matching `data/photos.json` to venue slugs.
5. Routes parse from `data/routes/*.gpx`, compute distance/gain/loss, link nearby venues, simplify geometry, and write to `public/data/routes.json`.
6. The tallest 3% of each venue type are marked `notable`.
7. Null optional fields are omitted from generated JSON to keep payload small.

## Browser storage

- Favourites: `localStorage` key owned by `src/lib/venues.ts`.
- Saved local routes: `localStorage` key owned by `src/lib/localRoutes.ts`.

Neither is considered authoritative for the public dataset. To publish a route, add the GPX to `data/routes/` and rebuild.

## Deployment

`.github/workflows/deploy.yml` runs on every push to `main`:

```bash
npm ci
npm run typecheck
npm run build   # VITE_BASE=/HillGPX/
```

The `dist/` folder is uploaded to GitHub Pages. No Python, no credentials, no runtime server.
